# Learning and Exploration Workflow

Use when the user wants to understand Lean or mathlib **in support of formal mathematics**: a theorem, tactic, proof pattern, project formalization, library API, or the formal version of a mathematical idea. This workflow is read-only unless the user explicitly asks to save or edit an exercise/example.

General Lean application-development topics outside formal mathematics are outside this Skill's scope.

## Contract

1. Resolve the learning target and the depth the user wants.
2. Inspect or search the relevant project/mathlib material before making concrete claims about current APIs or theorem names.
3. Match the explanation to the user's demonstrated level and requested style.
4. Verify important Lean claims when practical. Distinguish checked examples from conceptual or unverified explanations.
5. Adapt to observable interaction: change explanation or examples when a misunderstanding persists; advance when the user is succeeding.

For repository exploration, build a small map of the relevant formalization files and declaration dependencies rather than surveying the whole tree. For mathlib exploration, prefer canonical declarations and minimal examples.

Teaching styles such as a tour, Socratic questions, exercises, or game-like progression are presentation choices, not separate engines.

Completion is the requested mathematical/Lean understanding or learning artifact, not a code mutation or commit.
