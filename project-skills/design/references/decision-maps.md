# Decision maps

Use a decision map only when a large, branching effort benefits from a durable overview of what has been decided and what remains unresolved.

The map is an **index, not a second store of truth**. Each material decision should have one authoritative home. The map should give a short gist and point to that home rather than restating the full decision and creating another copy that can drift.

A useful map normally tracks:

- the objective or decision space being navigated;
- settled decisions, each linked to its authoritative detail when one exists;
- material unresolved questions or uncertainty;
- relationships that help explain which unresolved choices can change others.

Do not turn the map into a ticket taxonomy, claim protocol, session scheduler, or required project lifecycle. Update it only while it remains a useful navigation artifact; delete or stop maintaining it when ordinary project artifacts make it redundant.
