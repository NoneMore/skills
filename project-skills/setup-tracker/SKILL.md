# Setup Tracker

Configure tracker storage only. Read [ISSUE-MODEL.md](ISSUE-MODEL.md), then only the selected backend document. Publish both as a self-contained contract at `docs/agents/issues.md`.

## 1. Resolve backend and identity

Use an explicit backend choice. Otherwise use the one unambiguous intended GitHub repository; ask if several are plausible; use Local Markdown when no GitHub repository is intended.

Read `docs/agents/issues.md` if present. Backend identity is the backend plus its GitHub repository or Local Markdown issue root. For the same identity, make only missing setup changes. For a different identity, stop unless replacement was explicitly requested; replacement never migrates existing issues.

## 2. Configure

For GitHub, confirm repository identity, Issues availability, label read/write access, and existing tracker labels; create missing required labels while preserving unrelated ones. For Local Markdown, inspect and ensure `.tracker/issues/` exists.

Setup never modifies existing issues or issue files, or issue templates. Native relation capabilities are checked only by workflows that use them.

## 3. Publish and verify

Replace `docs/agents/issues.md` with this header, then the complete current `ISSUE-MODEL.md` and selected backend document:

```markdown
<!-- Generated by setup-tracker. Do not edit directly; re-run setup-tracker to rebuild. -->
# Issue tracker
Backend: <github|local-markdown>
Repository: <owner/repo>        # GitHub only
Issue root: .tracker/issues/    # Local Markdown only
```

The output is deterministic and self-contained: no Skill-relative dependency or appended stale content, and unchanged inputs for the same identity produce the same file.

Only when explicitly requested, add or update one project-instruction pointer saying `docs/agents/issues.md` contains the tracker contract and should be read before classifying, creating, or updating tracked work. Use the environment's instruction-authoring mechanism or effective runtime instruction target; do not guess a filename.

Verify required backend resources, backend identity, and exact inclusion of the current model and backend document. Report the configured backend and stop.
